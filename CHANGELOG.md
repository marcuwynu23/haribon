#### [Unreleased] — Wiring up what was already written

> 21 September 2026

Several subsystems below were written, unit-tested, and documented, but were
never connected to the running program. The documentation described behaviour the
binary did not have. This entry covers the wiring and the corrections. Nothing in
the earlier entries is deleted — this is what changed about them.

**Connected to the running program**

- feat(cli): add `cli/engine.go` — a swappable runtime that lets routing state be
  rebuilt and published atomically while serving. `proxy.Handler` now gets a
  delegating object and never needs to know a rebuild happened.
- fix(cluster): start the gossip node from `startCommand`. `internal/cluster` was
  imported only by its own test, so no node ever ran and the cluster metrics were
  never registered.
- fix(config): apply reloads. `Snapshot.Load()` was only ever called at startup, so
  `StartWatcher` swapped a snapshot nothing read. Added `StartWatcherHook` and
  wired `--watch_config` / `SIGHUP` to a rebuild.
- fix(discover): `Provider.Watch` polled and discarded its results. The polling
  loop now lives in `cli/engine.go` and a changed list triggers a rebuild.
- fix(logging): `setupLogging` built an `exporters` slice and dropped it on return,
  so `logWriter` stayed stdout and the configured log file was created but never
  written to (0 bytes).

**Log exporters — implemented rather than stubbed**

- feat(logging): Loki via `POST /loki/api/v1/push`, Elasticsearch via
  `POST /_bulk` (NDJSON), Fluent Bit via the `forward` protocol over TCP.
- feat(logging): add `loki`, `elasticsearch` and `fluentbit` config blocks
  (`url`, `labels`, `index`, `addr`). The plain `exporters:` string list keeps
  working; each destination buffers in the background so a slow collector cannot
  slow down traffic.
- feat(logging): implement `log_format: text`, which was validated and then ignored.

**Correctness**

- fix(balancer): `ip_hash` never read the client address — it advanced a shared
  index and was round-robin in disguise. Added `NextForIP`, which the proxy calls
  with the real client IP.
- fix(balancer): expose `ActiveConns()` so `haribon_active_conns` is populated. It
  was defined but never called outside its own package.
- fix(cluster): `listenLoop` unmarshalled the whole 4096-byte buffer including
  trailing NUL bytes, so every gossip message failed to parse and was dropped.
- fix(cluster): a replica that went away left its "unhealthy" verdict in place on
  every other replica forever, keeping a healthy backend out of rotation
  permanently. Peer findings now expire after roughly three gossip rounds (never
  less than 15s), and only first-hand findings are gossiped — so the peer set must
  be a full mesh. Documented in `docs/clustering.md`.
- fix(cluster): `haribon_cluster_peers` could only ever decrease. It now counts
  replicas actually heard from, and forgets them when they go quiet.
- fix(cluster): `Stop()` panicked if called twice; `Start()` now returns an error
  when the gossip port cannot be bound, instead of failing silently.
- fix(cluster): `node_id: "${HOSTNAME}"` was never expanded, so every replica
  shared one literal node ID and `MergeGossip` — which drops a message whose
  `NodeID` matches its own — silently ignored all of them. `${VAR}` is now
  substituted before the config is parsed, and an unresolved reference is a
  startup error.
- fix(config): `Validate(cfg Config)` took its argument by value, so the defaults
  it filled in were discarded. It also now actually applies
  `schema/haribon-config.schema.json`, which `haribon validate` previously never
  opened.
- fix(discover): the DNS provider returned bare addresses (`10.0.0.1`), which are
  not usable backend URLs. Added `dns_port`, stamped onto each resolved address.
- fix(config): return `balancer.ErrInvalidWeight` for a negative weight. The
  sentinel existed but was never returned. A `weight` of `0` or an omitted key
  means `1`; the schema minimum was corrected from 1 to 0 to match.

**Documentation**

- docs: correct every claim that described unimplemented behaviour, across
  README.md, USER_GUIDE.md, `docs/*.md`, the HTML site, and the sample comments.
- docs: correct `haribon_active_conns` — it is populated only while
  `least_connections` is the configured strategy.
- docs: correct `haribon_requests_total` — it counts attempts, so a retried
  request appears against both servers.
- docs: correct `haribon_cluster_term` — it is the highest update counter this
  replica has recorded, not a count of health updates seen.
- docs: mark ROADMAP issue #4 (Management UI + admin API) as **not implemented**.
  The `admin:` block is parsed and defaulted but nothing listens on it.
- fix(samples): the Kubernetes manifest used a Deployment with
  `peers: ["haribon-0:7946", ...]`, which a Deployment never produces, and had no
  `backends:` at all — every request would have been a 503. Rewritten as a
  StatefulSet with per-pod DNS names, a backends list, and a `preStop` hook.
- fix(samples): docker-compose published host port 4444 twice and ran backends
  from an image that could not serve anything. Both fixed.
- fix(docs): repair mojibake in README.md, `docs/enterprise-runbook.md`,
  `docs/installation.html` and `docs/samples.md`.
